# Example — Compact vs Overengineered

**Task:** “Rewrite this customer email to sound more professional and concise.”

## Correct

Use D0/D1: role + task + tone + complete email output.

## Overengineered

Do not add Git safety, multi-agent delegation, recovery plans, current model research, twelve execution phases, or an extensive Definition of Done.

**Boundary rule:** structure is valuable only when it changes expected execution quality or safety.
