# Use plugin manifests as the marketplace source contract

## Context and Problem Statement

Codex Essentials distributes plugins from `plugins/<plugin-id>`. Each plugin
has its own `.codex-plugin/plugin.json`, README, changelog, license, and
component files. The repository also publishes
`.agents/plugins/marketplace.json`, but that file must not become a second
hand-maintained source of truth.

How should the repository keep plugin metadata, plugin versions, and the
marketplace catalog synchronized?

## Decision Drivers

- Keep each plugin self-contained and distributable.
- Avoid manual edits to generated marketplace metadata.
- Keep plugin versions uniform for the initial public baseline.
- Make validation possible without requiring Node-specific generator code.

## Considered Options

- Maintain plugin manifests and marketplace entries independently.
- Generate plugin manifests from one central repository file.
- Treat plugin manifests as source and generate the marketplace catalog.

## Decision Outcome

Chosen option: "Treat plugin manifests as source and generate the marketplace
catalog" because it keeps package identity at the package boundary and makes
catalog drift detectable.

All `plugins/*/.codex-plugin/plugin.json` files use `version: "0.1.0"` for the
initial baseline. Each plugin changelog is reset to an initial `0.1.0` release
dated `2026-09-11`. The marketplace catalog is regenerated by
`scripts/generate_marketplace.py`, not edited by hand.

### Consequences

- Good, because plugin identity and component declarations live in one place.
- Good, because marketplace generation is reproducible.
- Bad, because plugin metadata edits must be followed by generator validation.

### Confirmation

Run `npm run marketplace:build`, `npm run marketplace:test`, and
`npm run check`.
